## 一、项目背景与问题描述

二维栅格仿真地图上，人工玩家与机器 AI 开展寻宝对抗游戏。地图包含空地、障碍物、宝藏、陷阱。
每回合投掷骰子得到本回合最大有效成功移动步数 N；玩家输入一组移动方向序列；试图走向障碍物时提示
"障碍物无法通过，不消耗步数"，只有成功踏入合法格子才消耗有效步数。踏入宝藏/陷阱立刻触发对应效果。
回合全部移动结束后的终点坐标重合才触发对战，依据双方分数结算奖惩。
游戏结束条件：地图所有宝藏被拾取完毕，对比双方分数判定胜负。

三种模式定义：

1. 简单模式
   - AI：贪心策略（BFS 优先选择收益/距离比最高的宝藏，不做博弈推演，不预判对手）
   - 可见性：完全信息，障碍物、宝藏、陷阱全部对人工可见。
2. 普通模式
   - AI：OPT 最优 AI（Expecti-Max 期望极大极小 + α-β 剪枝 + 记忆化 DP）
   - 可见性：完全信息，障碍物、宝藏、陷阱全部对人工可见。
3. 困难模式
   - AI：OPT 最优 AI（Expecti-Max 期望极大极小 + α-β 剪枝 + 记忆化 DP）
   - 可见性：障碍物、宝藏可见；陷阱初始对人工隐藏，伪装为空地；任意玩家踩到陷阱后永久暴露；
     机器 AI 始终读取底层完整真实地图。

说明：简单模式重新恢复贪心 AI 仅用于简单模式；普通、困难模式使用 Expecti-Max 最优博弈算法。

## 二、完整游戏通用规则（三模式共用）

地图元素
- 0：空地；1：障碍物（墙体，不可落脚）；正数：宝藏；负数：陷阱。

回合与骰子
- 轮到玩家回合，投掷骰子 (1-6 均匀随机)，得到本回合最大有效成功移动步数 N。
- 玩家可输入少于 N 步的方向序列；输入 end 可直接放弃剩余步数结束回合。

移动核心规则（不变）
1. 玩家输入方向序列（仅上下左右，禁止斜向），本回合最多完成 N 次成功移动。
2. 逐条处理指令：
   a. 若已经完成 N 次有效移动，直接结束移动阶段。
   b. 计算下一步候选坐标；
   c. 候选坐标越界或者是障碍物：日志输出 "该方向为障碍物，无法通过，不消耗步数"；坐标不变，
      不消耗有效步数，继续处理下一条指令。
   d. 坐标合法（空地/宝藏/陷阱）：玩家移动过去，消耗 1 点有效步数；立刻触发格子效果：
      拾取宝藏加分（宝藏消失）、踩陷阱扣分（陷阱消失）。
3. 指令遍历完毕或有效步数耗尽，移动阶段结束。
4. 以最终停留坐标判断是否对战；中途路过对手不触发对战。

对战结算规则（不变）
- 回合移动全部结束，双方坐标重合，触发对战：
  1. 读取对战瞬间双方分数；
  2. scoreA > scoreB：胜者 +5 分，败者 -5 分；败方尝试移动至相邻合法空地；周围全障碍则位置不变，分数依旧结算；
  3. scoreB > scoreA：反之；
  4. 分数相等：平局，分数、位置均不变。

游戏结束条件
- 地图所有宝藏全部拾取完毕，输出双方分数，判定本局胜负。

三种模式差异对照表

| 模式 | 机器 AI 算法 | 陷阱可见性（人工视角） |
| --- | --- | --- |
| 简单模式 | 贪心 AI（BFS，只看自身宝藏收益，无博弈推演） | 陷阱完全可见 |
| 普通模式 | OPT Expecti-Max 最优 AI | 陷阱完全可见 |
| 困难模式 | OPT Expecti-Max 最优 AI | 陷阱初始隐藏，踩中后暴露；机器始终可见全部陷阱 |

## 四、系统六大核心模块架构

1. 地图模块 MapModule
   1. 底层真实二维地图；标记宝藏、陷阱是否触发。
   2. 随机地图生成子模块：宽高、障碍物、宝藏、陷阱数量；参数校验；BFS 连通校验；保证玩家出生点不重合。
   3. get_view_map(mode) 视图生成函数：
      - 简单/普通模式：视图 = 真实地图，全部格子展示。
      - 困难模式：未触发陷阱伪装为空地 0；触发后显示真实负值。
   4. txt 地图读写保存。

2. 寻路与移动模拟模块 PathModule
   sim_player_multi_step(true_map, start_pos, move_seq, max_valid_step)
   逻辑不变：障碍物指令失败，不消耗有效步数；合法移动才消耗步数；途中触发宝藏、陷阱。
   ⚠ 注意：贪心 AI、Expecti-Max 内部移动模拟逻辑，必须与本函数行为 100% 对齐。
   工具函数：
   - BFS 连通校验；
   - get_adjacent_empty()：对战结算后获取败方可推开的相邻空地。

3. AI 模块 AiModule（拆分两套 AI）
   3-1 贪心 AI（仅简单模式使用）
   - 不再作为对照组实验算法，专门作为简单模式的机器对手。
   1. BFS 计算自身到每一个剩余宝藏的最短距离；计算 宝藏分数 / 距离 性价比；选择性价比最高宝藏为目标；
   2. BFS 寻路向目标宝藏生成移动方向序列；不预判对手、不做博弈推演、不考虑对战风险。

   3-2 OPT 最优 AI（普通、困难模式）
   算法：Expecti-Max 期望极大极小 + α-β 剪枝 + 记忆化 DP 缓存
   - 机会节点处理骰子 1-6 随机；MAX/MIN 节点模拟玩家行为；估值函数 eval = scoreHuman − scoreOpt。
   - 博弈状态 key：(ax, ay, bx, by, scoreHuman, scoreOpt, remain_treasure, remain_trap, turn)
   - 对外接口：get_opt_move(state, dice_N) 返回最优移动序列。
   - 工程约束：搜索深度推荐 3-4；机器 AI 永远读取底层完整真实地图，不受视图影响。

4. 对战结算模块 BattleModule
   trigger_battle(true_map, posA, posB, scoreA, scoreB)
   仅回合移动全部结束后调用；更新分数、处理败方推开逻辑。

5. 仿真模拟器 Simulator
   1. run_human_vs_ai(game_mode) 人机对抗主入口，根据 game_mode 选择调用贪心 AI / OPT-ExpectiMax AI；
      并调用 get_view_map() 生成对应模式的玩家视图。
   2. 辅助测试函数：run_machine_vs_machine()、run_human_vs_human()。
   3. 批量仿真：批量生成随机地图；统计对战次数、踩陷阱频次、得分差、耗时。

6. 分治分块优化模块 DivideConquerModule
   针对 OPT-ExpectiMax，用于大地图近似求解；贪心 AI 不需要分治优化。

表现层
- 控制台 IO（必做）；GUI（选做加分）

## 五、核心算法说明

1. 随机地图生成：打乱坐标分配格子；参数校验、BFS 连通校验，保证出生点不重合。
2. BFS：地图连通校验；贪心 AI 寻路；对战后寻找空位。
3. 贪心策略（简单模式）：基于 BFS 计算宝藏性价比，只追求自身拿高分，无博弈对抗推演；速度快，策略短视。
4. Expecti-Max 期望极大极小（普通/困难模式）：处理骰子机会节点，α-β 剪枝 + 记忆 DP 加速；
   内部移动模拟和模拟器行为严格一致。
5. 分治分块优化：大地图切分，子块 Expecti-Max 求解，合并得到近似解，牺牲精度换取速度。
6. 视图-真实地图隔离：根据模式生成玩家可见视图；困难模式仅对人工隐藏未触发陷阱。

## 八、项目亮点（报告）

1. 多模式分层难度设计：简单模式使用贪心快速上手；普通模式完整信息下体验 Expecti-Max 最优博弈；
   困难模式增加陷阱隐藏提升挑战。
2. 融合多种经典算法：贪心、BFS、Expecti-Max 期望极大极小博弈、α-β 剪枝、记忆化 DP、分治分块优化。
3. 精细化移动规则：撞障碍物指令失败不消耗有效步数；AI 内部推演逻辑和真实模拟器行为完全对齐。
4. 骰子随机多步移动、回合终点触发对战；博弈需要权衡收集资源与对战搏分风险。
5. 参数化随机地图生成，支持自动化批量仿真定量实验；小规模精确求解、大规模分治近似求解，
   体现精度-速度工程权衡。

## 九、项目局限性（报告）

1. Expecti-Max 状态空间随地图、宝藏数量指数增长，搜索深度不能设置过高，否则机器思考时间长。
2. 困难模式仅对人工隐藏陷阱；OPT 机器 AI 仍然掌握全局地图真值；双向未知陷阱需要 POMDP 算法，实现复杂。
3. 分治模块输出近似最优解，存在一定结果误差。
4. 贪心 AI 只考虑自身宝藏收益，不会预判对手抢夺宝藏、对战风险，策略存在明显短板。
