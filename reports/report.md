## 1. 摘要

本项目在二维栅格地图上实现"人工玩家 vs 机器 AI"的寻宝对抗博弈平台，按需求拆分为**简单 / 普通 / 困难**三种模式，并区分两类 AI 与两类陷阱可见性：

| 模式 | 机器 AI | 陷阱对人工可见性 |
| --- | --- | --- |
| 简单 EASY | 贪心 BFS（收益/距离性价比） | 完全可见 |
| 普通 NORMAL | OPT Expecti-Max（+ α-β + 记忆化 DP） | 完全可见 |
| 困难 HARD | 同上 OPT | 初始隐藏、踩中后永久暴露；机器始终读真值 |

交付六大模块（`MapModule` / `PathModule` / `AiModule` / `BattleModule` / `Simulator` / `DivideConquerModule`）、控制台必做版本（七项主菜单）、批量仿真实验驱动，以及选做的 PyQt6 可视化界面。

**主要实测结论（均在 12×12、270 局正式样本、T=3/K=24、固定 seed 下）**：

1. **算法替换显著有效**：把简单模式的贪心换成 OPT，AI 净分差提升 **+16.51**（95% CI [+11.07, +22.51]），AI 胜率（严格口径）**0.389 → 0.600**，AI 自身踩陷阱次数下降 **−0.64**（CI [−0.84, −0.46]），主动对战次数 **+1.32**（CI [+0.74, +1.96]）——三项区间均不含 0。
2. **陷阱隐藏本身有效**，但**只有在人工代理会利用可见信息时才可被观测**。使用"陷阱盲"代理时 NORMAL 与 HARD 的 90 局结果**逐位相同**（配对差全为 0）；换成会避让可见陷阱的 `CAUTIOUS` 代理后，人工踩陷阱次数由 0.00 升到 **1.01**，90 个配对单元中 **50 个**终局发生分歧，出现"NORMAL 绕开、HARD 踩中同一格"的可复现实例。该结论在 10×10 单体 OPT 基线上独立复现（踩陷阱 0.00 → 1.00，分差配对差 +3.69，CI [+0.26, +8.10]），并随陷阱密度单调增强（陷阱数 2/6/12 → Δ 踩陷阱 +0.30 / +1.03 / +2.13）。这是**实验设计缺陷**的发现与修复，而非规则作用为零。
3. **分治近似换来 4.8–5.7× 加速**，代价可测：同图同骰下 `|ΔU|` 均值 +5.02 但 95% CI 跨 0（本规模下检不出平均效用差），**逐决策动作一致率仅 34.5%**（决策轨迹显著不同），而 AI 胜率反而更高（0.600 vs 0.411，CI [+0.100, +0.278]）。
4. **α-β 剪枝在本问题的机会节点上实测几乎不生效**：默认安全配置下开关剪枝的节点数完全相同（1118 vs 1118，缓存关时 5489 vs 5489）。真正的加速器是"只缓存精确值"的记忆化 DP（5489 → 1118 节点，4.9×）。这是一个**真实的零结果**，报告如实记录。
5. **规格一致性可验证**：需求第七节 5 个关键用例全部自动化通过；全量回归 **374 passed / 2 skipped / exit 0**。

> ⚠ 全文不会把限深、裁剪、分治的结果称为"全局最优"。准确口径是"**给定深度 d 与候选集内的最优，且在安全剪枝下与原树同值**"。

## 2. 问题定义与规则实现

### 2.1 地图与元素编码

| 编码 | 含义 |
| --- | --- |
| `0` | 空地（可落脚） |
| `1` | 障碍物 / 墙体（不可落脚，**唯一表示墙**） |
| `>= 2` | 宝藏（分值） |
| `< 0` | 陷阱（扣分） |

静态底图（`terrain`）与资源层（`treasure_values` / `trap_values`）分离，动态层（`remaining_treasures` / `active_traps` / `revealed_traps`）独立维护。`TrueMap` 与 `ViewMap` 是**两个不同的冻结类型**，AI / Path / Battle 只接 `TrueMap`，渲染层只接 `ViewMap`。

### 2.2 移动规则（规格第二节）

逐条处理指令；命中越界或墙时**不消耗有效步数**、坐标与分数不变，产生 `BLOCKED` 事件，文案逐字为 `该方向为障碍物，无法通过，不消耗步数`；合法踏入消耗 1 步并**立即**结算资源。成功步数达到骰子值 N 后立即停止并忽略剩余指令。

### 2.3 对战与终局

仅在**回合全部移动结束后**、双方终点坐标重合时触发一次对战：分数不等则胜者 `+5`、败者 `-5`，败者被推到相邻"从未布置资源"的空格（无候选则原地不动但分数照改）；同分则平局不推开。所有宝藏被拾取即终局；拾取最后一枚宝藏的回合**先对战再判终局**。

### 2.4 Lead 裁决的规格缺口（D1–D11）

需求文档存在若干歧义，均在 [00-framework.md](../docs/00-framework.md) 与 [06-interface-freeze.md](../docs/06-interface-freeze.md) 中显式裁决并冻结。关键几条：

| 编号 | 缺口 | 裁决 |
| --- | --- | --- |
| D1 | `1` 同时被描述为墙与"正数宝藏" | `1` 只表示墙；宝藏分值从 `2` 起 |
| D2 | "踩后陷阱消失"与"永久暴露"冲突 | 效果一次性；`revealed_traps` 永久保留并显示原负值，再踩不扣分 |
| D4 | 败方"相邻合法空地"未定义 | 仅取"底图 0 且从未布置资源"的格，邻序上/左/下/右 |
| D5 | MIN（人类）行为模型未定义 | 候选只由 `ViewMap` + `PublicStateView` 生成（防泄露），MIN 在其中选对 AI 最不利的真实结果 |
| D9 | 对局可能不终止 | 单局 `max_turns=500`，超时记 `draw_timeout=True` 且不计正常胜负 |
| D11 | 最后一枚宝藏与对战顺序未定义 | 先终点对战、再判终局 |

## 3. 系统架构与数据模型

### 3.1 模块与依赖方向

```
__main__ → console_io / gui → (models 的 GameIO 协议)
__main__ → simulator → map_module → path_module → models
                    → ai_module → greedy_ai / opt_ai / divide_conquer_module
                    → path_module、battle_module → models
experiments/run_batch → simulator、map_module、models
```

单向依赖，无环：`PathModule` 不反向依赖 `MapModule`，`DivideConquerModule` 不 import `opt_ai`（通过注入的局部求解回调解耦），`gui.py` 与 `console_io.py` 不 import 任何真值类型。

### 3.2 关键设计决策

| ADR | 决策 | 被否决的方案及原因 |
| --- | --- | --- |
| 01 | 控制台纯标准库 | 全依赖 PyQt：增大部署门槛 |
| 02 | `TrueMap` / `ViewMap` 双类型隔离 | 单一可变二维数组：历史暴露与 AI 预测互相污染 |
| 03 | `sim_player_multi_step` 是**唯一**移动语义真相源，AI 内部推演复用它 | AI 手写第二份移动逻辑：撞墙步数与途中取物必然漂移 |
| 04 | 静态底图与动态资源分离 | 原地把负值改 0：丢失"永久暴露"历史 |
| 06 | chance 节点只在有可证上下界时剪枝 | 对机会节点套普通 α-β：期望值错误 |
| 08 | 注入 `random.Random(seed)`，搜索不消耗游戏 RNG | 全局 `random`：结果随搜索顺序漂移 |

### 3.3 真值隔离的强制方式

- `PathModule.sim_player_multi_step` / `AiModule.get_opt_move` / `BattleModule.trigger_battle` 入口做 `isinstance` 守卫，传 `ViewMap` 抛 `TypeError`（有测试）。
- `GameIO.next_action(seat, dice_N, view, state_view)` 与 `render(view, state_view, events)` 只接收 `ViewMap` + `PublicStateView`；`PublicStateView` 结构上不含 `TrueMap`。
- HARD 模式下未触发陷阱在视图里就是 `0`；静态审计确认 `console_io.py` / `gui.py` 中**没有** `true_map` / `trap_values` / `active_traps` 的引用。

## 4. 算法设计与正确性

### 4.1 贪心 AI（仅简单模式）

1. 从机器座位对**所有剩余宝藏**跑一次 BFS 求最短成功步距离（复用距离表，不逐个重跑）；
2. 性价比 `value / max(distance, 1)`，整数交叉相乘比较避免浮点误差；
3. 平局链：比率 → 宝藏分值 → 距离 → 目标坐标字典序；
4. 用 `bfs_path`（邻序上/左/下/右）生成方向序列，取前 `dice_N` 条。

复杂度 `O(V+E+T)` 时间、`O(V)` 空间。**局限**：性价比不扣除沿途陷阱期望、不考虑对手抢夺与对战风险，是有意的教学基线。

### 4.2 OPT Expecti-Max（普通 / 困难模式）

| 节点 | 含义 | 取值 |
| --- | --- | --- |
| MAX | 机器 AI 行动 | 对 `U = scoreOpt − scoreHuman` 取最大 |
| MIN | 人类模型行动（候选仅来自视图） | 对 `U` 取最小 |
| CHANCE | 骰子 1..6 | 等权 `1/6` 期望；根骰已知不再掷 |
| 叶 | 深度 0 或终局 | `U = −eval`，其中报告口径 `eval = scoreHuman − scoreOpt` |

**方向极易搞反**：报告用 `eval = scoreHuman − scoreOpt`，而搜索内部必须优化其相反数 `U`。把 `eval` 直接喂给 MAX 会让 AI 主动求败——这是实现期列为一号风险（R04）并在测试中固定住的点。

状态键包含 `map_id`、规范化座位、两人坐标、双方分数、`remaining/active/revealed` 三个集合、`turn`、`node_kind`、`known_dice`、`remaining_depth`、`mode`、`human_model_id`、`candidate_limit`、`partition_context`。**只有精确值可入缓存**，界值与超时不得写入。

α-β 在机会节点下的正确处理：安全初版对每个 chance **枚举六面并传全窗口**求精确值，父 MAX/MIN 仅对已求得的精确子值做兄弟剪枝；带区间的 chance 剪枝（`_Bound(lo, hi)` + 窗口传播）已实现且与全枚举逐状态同值，但实测不减少节点，默认关闭（见 §7.4）。

### 4.3 分治分块（仅大地图 OPT）

面积 `V >= 144` 时按确定性 4×4 切块；**块边界不作墙**，跨块路线用**全图 BFS** 求解；局部子问题只限制"关注的目标资源集合"，不删除真实墙 / 陷阱 / 宝藏 / 对手；返回序列必须由全图 `sim_player_multi_step` 验证；`SearchDiagnostics.approximate=True`。

> 工程发现：若每个局部子问题都用全局深度与 K，分治反而比单体慢 3–5×。落地时局部子问题取 `depth−1, K/2`，这正对应设计方案"牺牲精度换速度"的定位。

### 4.4 正确性验证入口

| 性质 | 验证方式 | 实测 |
| --- | --- | --- |
| 剪枝 = 无剪枝 | 小图同候选集比较根 U 与动作 | 4 组 seed 全部逐位相同 |
| 缓存开 = 缓存关 | 同上 | 4 组 seed 全部逐位相同 |
| 根预测 = 全图重放 | `root_final_pos/root_score_delta` 对比 Path 重放 | 6/6 组一致 |
| 撞墙免费 | 两张仅墙位置不同的图跑同一序列 | 成功位移完全相同 |
| 视图隔离 | 只改隐藏陷阱位置的两张真图 | 陷阱盲代理候选完全一致 |

### 5.5 HARD 隐藏陷阱的端到端表现

真实控制台输出（Lead 亲自运行）：

```
---- 第 1 回合 | 当前：A（人类） | 骰子最大有效步数 N = 1 ----
【上回合日志】
移动到 (3, 0)
【踩到隐藏陷阱！扣除 2 分，陷阱已暴露】
```

实现要点：`PathModule` 是**模式无关**的纯内核，只产生通用 `TRAP` 事件；HARD 专属提示由 `Simulator` 依据"该陷阱在本次移动前不在 `revealed_traps`"**改写**该条事件文案（保持"每次结算恰好 1 条 TRAP 事件"的不变量），扣分值仍为原始负值。提示帧之前的全部人工输出经断言**不含**该陷阱坐标与负值。

### 6.2 人工代理的两个版本（本报告的核心方法论修正）

| 版本 | 座位 A 策略 | 是否使用可见陷阱信息 |
| --- | --- | --- |
| v1 | `GATHER` | ❌ 陷阱盲（候选集纯几何口径） |
| v2 | `CAUTIOUS` | ✅ 对视图上可见负值格计惩罚并绕行 |

`CAUTIOUS` 的评分键（全部只在**视图**上计算，确定性、不消耗随机数）：
① 途经可见负值格数 → ② 这些格的扣分绝对值之和 → ③ `−`途经可见宝藏收益 → ④ 终点到最近可见宝藏的距离 → ⑤ 有效步数 → ⑥ 方向序列字典序。
候选集 = 原几何候选 ∪ "把可见负值格当墙"的 BFS 候选（绕行路线自然出现），去重后按上述键升序。

关键性质：**HARD 下未触发陷阱在视图里就是 `0`**，因此 `CAUTIOUS` 在困难模式下"看不见所以会踩进去"——这正是需要隔离的机制。GATHER 的既有行为经 221 条快照前后对比**零差异**证明未被改动。

### 7.5 陷阱数量分层扫描：可见性效应随陷阱密度单调增强（v2，CAUTIOUS）

固定 12×12、10 个地图 seed × 3 个骰序 seed = 30 配对单元/组，只改陷阱数量：

| 陷阱数 | 配对单元 | 人工踩陷阱（NORMAL） | 人工踩陷阱（HARD） | Δ 人工踩陷阱 | Δ 分差（HARD−NORMAL，稳健） |
| --- | --- | --- | --- | --- | --- |
| 2 | 30 | 0.00 | 0.30 | **+0.30** | +2.07（n=30） |
| 6 | 30 | 0.00 | 1.03 | **+1.03** | +4.47（n=30） |
| 12 | 30 | 0.00 | 2.13 | **+2.13** | +6.28（n=29，剔除 1 个往复循环局） |

两个趋势都是**单调递增**的：

1. **Δ 人工踩陷阱次数与陷阱数量成正比**（0.30 → 1.03 → 2.13）：在 NORMAL 下人工始终 0 次踩陷阱（陷阱可见、`CAUTIOUS` 全部绕开），在 HARD 下踩中次数随陷阱密度线性上升。这直接验证了"陷阱越多，隐藏代价越大"。
2. **Δ 分差随陷阱密度上升**（+2.07 → +4.47 → +6.28）：陷阱越密集，可见性差异对最终比分的杠杆越大。

### 7.6 消融：α-β 剪枝与记忆化 DP（真实零结果）

| 配置 | 节点数（seed=0/1/2/3） | 根 U 与动作 |
| --- | --- | --- |
| 缓存开 + 剪枝开 | 221 / 236 / 135 / 205 | 四组合逐位相同 |
| 缓存开 + 剪枝关 | 221 / 236 / 135 / 205 | 同上 |
| 缓存关 + 剪枝开 | 385 / 389 / 185 / 378 | 同上 |
| 缓存关 + 剪枝关 | 385 / 389 / 185 / 378 | 同上 |

**剪枝开关的节点数完全相同**。原因：在"安全初版"配置下机会节点恒返回**精确**期望值，α/β 窗口无法被可靠收紧，因此剪枝条件不可满足。真正的加速器是"只缓存精确值"的记忆化 DP：**5489 → 1118 节点（4.9×）**。

带区间界（`_Bound(lo, hi)` + 窗口传播）的 chance 剪枝**已实现**且与六面全枚举逐状态同值，但在当前保守界 `R = Σ|宝藏| + Σ|陷阱| + 10d` 下实测**不减少**节点（无缓存时 8786 vs 5489，反而更差），故默认关闭。这是消融实验中的真实零结果，如实记录而不粉饰。

### 7.7 异常案例：往复循环导致的对战堆积（v2，NORMAL）

v2 的 NORMAL 组出现 3 局超时（3.3%）与 2 局对战次数 730+（2.2%）；`traps=12` 分层扫描中也出现 1 例（753 次对战）。Lead 用真实 Simulator 逐步重放定位到机制：

- 病例：`map_seed=63, dice_seed=100045, NORMAL`。地图中 `(1,1)` 有陷阱，剩余宝藏位于其后方；`CAUTIOUS` 拒绝踩陷阱而反复绕行至 `(1,2)`；AI 同样前往该区域。两者在瓶颈格 `(1,2)` **每回合相遇**，每次触发 `±5` 对战，分数线性堆积至 `A=−3674 / B=3688`，直到 `max_turns=500` 截断。
- 位置计数证实循环：`(A,1,2)` 出现 246 次，`(B,1,2)` 246 次，`(B,2,2)` 245 次。
- **同一地图同一骰序在 HARD 下正常终局**（10 回合，`A=6 B=8`）：因为人工看不见 `(1,1)` 的陷阱，第一步就踩掉它，路径打开，无循环。

**定性**：这不是规则缺陷。需求未要求对局必然终止；反复入场反复结算对战是规则的自然结果，`max_turns` 兜底也正常工作（`draw_timeout=True`、`winner=None`）。这是**启发式代理的病理行为**：一个"绝不踩陷阱、又必须穿过陷阱去拿宝藏"的确定性代理会永远卡在门口。真实人类会做出不同取舍。

**对统计的影响与处置**：对策次数与分差均值影响极大（NORMAL 对战均值 17.88 vs 中位数 0）。因此：
- 报告以**中位数**与**病态局占比**作为主口径；
- 剔除 2 个 >20 次对战局与 3 个超时局后（n=87），NORMAL 分差均值 **+11.98 ± 27.20**，与 §7.1 的 v1 结果一致，说明**病态局不影响主结论**；
- `|ΔU|`、动作一致率等分治结论用同一网格同 seed 配对，不受跨模式污染。

### 7.10 状态爆炸的因素分解（Lead 实测，`tools/lead_branch_probe.py` 等）

这部分回答"到底是什么引起了状态爆炸"。全部数字来自运行时插桩（包装 `_Search._expand` / `search_chance`）与单变量扫描，不是设计文档的推导。

**① 唯一的指数因子是搜索深度**

| depth | 总节点 | 相对上一层 | 耗时（N=3, K=24, 12×12） |
| --- | --- | --- | --- |
| 1 | 7 | — | 2.1 ms |
| 2 | 190 | 27.1× | 15.5 ms |
| 3 | 2,184 | 11.5× | 289.7 ms |
| 4 | 14,484 | **6.6×** | 2,523.1 ms |

**② 每一层的分支因子 ≈ 33：`6（骰子）× 5.55（人类候选）`**

| 节点类型 | 实际规模（N=6, depth=3, 12×12） |
| --- | --- |
| MAX 展开次数 | **1**（只有根节点） |
| MIN 展开次数 | **1,344**（占全部展开的 99.9%） |
| CHANCE 节点数 | 302，每个固定 6 面 → 骰子分支合计 1,812 |
| MIN 去重后子节点 | 均值 **5.55**（候选 7 个 → 去重后 5.55） |
| MAX 去重后子节点 | 均值 **9.0** |

**③ 真正的候选数远小于"指令序列爆炸"**

| N | 实际候选（MAX 节点） | 穷举理论上限 `Σ4^k` | 压缩比 |
| --- | --- | --- | --- |
| 1 | 4 | 5 | 1.3× |
| 3 | 7 | 85 | 12× |
| 6 | **9** | **5,461** | **607×** |

原因有两层：动作是**结构化生成**的（空动作 + BFS 宝藏前缀 + 靠近对手 + 远离对手），不做盲目 4 方向穷举；而且不同序列按**完整结果**去重（终点 + 双方分数 + 三个资源集合）。

**④ 三个被实测否定的"直觉因子"**

| 直觉 | 实测 |
| --- | --- |
| 候选上限 K 是关键旋钮 | **无效**：K=8/24/64 → 2,842/3,146/3,146 节点。实际候选只有 4–9 个，`K=24` 从未触发截断 |
| 地图越大/资源越多越爆炸 | **几乎无影响**：8×8→14×14 只有 642→2,003 节点；宝藏 4→30 个反而 417→1,858（非单调）。资源数只影响启发式质量与深度预算，不进入分支因子的指数 |
| MIN 候选生成有重复可缓存 | **无效**：1,344 次调用可命中 **0** 次（每个 MIN 节点的视图状态唯一） |

**⑤ 决定性约束：终局即截断**

`remaining_treasures` 为空就终局，所以有效深度被**剩余宝藏数 + 1** 封顶。这解释了为什么宝藏 4 个时只有 417 节点：depth=3 的搜索很快撞上"宝藏已收完"。这是唯一能让搜索自动变浅的机制。

**⑥ 结论：加速该往哪投**

| 手段 | 预期 | 依据 |
| --- | --- | --- |
| **降低 depth 或做自适应深度** | 每减 1 层约 ÷7～11 | ① 的实测比值 |
| **收紧 chance 上下界让 α-β 生效** | 可能省掉大部分 MIN/chance 子树 | §7.6 证明当前界太宽导致剪枝条件不可满足；MIN 占 99.9% 展开 |
| **把 MIN 从"策略集最坏情况"改为单动作预测** | 实测 **3.7×** 提速（58.2→15.8 ms）、节点 1118→366 | §7.12；因为 MIN 每节点只展开 1 个子节点而非 ~5.55 个 |
| **做"共享人类骰子"的近似** | 把 `6^(d−1)` 降到 `6^(d−2)` 量级 | 双方骰子独立是乘性因子（②） |
| 分治降低有效搜索规模 | 已实测 4.8–5.7× | §7.4 |
| 换 C++ | 常数因子，不动指数 | 节点数与语言无关 |
| 扩大 K、加大地图、加资源 | **无效** | ④ |

### 7.12 人类建模方式的影响（Lead 实测，`tools/lead_ab_human_model.py`）

**动机**：原 MIN 节点枚举整个确定性策略集，取对 AI 最不利者（"最坏情况"）。这让人设在搜索里显得完美，AI 过度保守，且每层要为 5.55 个人类走法各展开一棵子树。

**改动**：默认改为 `human_model="heuristic"`——按**一个**确定性策略（默认 GATHER）预测人类走法，MIN 因此退化为单动作预测。旧口径保留为 `human_model="worst_case"` 供消融。

| 维度 | 实测结果 |
| --- | --- |
| **行为差异** | 12 个局面（3 图 × 4 骰值）中 **4 个动作改变（33%）**。例：`seed=7, N=2` → `s,s` 改为 `w`；`seed=7, N=3` → `s,s,d` 改为 `w` |
| **根效用（同一局面）** | depth=1/2/3 的根 U 均显著回升（如 depth=3：−17.67 → **−6.56**），说明 AI 不再把未来估值压得过低 |
| **性能** | 单次决策 **58.2 ms → 15.8 ms（3.7×）**；搜索节点 **1118 → 366**；DP 命中率 29.1% |
| **棋力** | 24 局同图同骰配对：AI 胜率 **0.409 vs 0.409**；分差配对差 −1.08，95% CI [−3.25, +0.42] **跨 0**；对战次数 +0.13，CI [+0.00, +0.33] 跨 0 |

**结论（如实记录）**：这次改动带来的是**速度提升 3.7× + 不再过度保守**，**没有可检出的棋力提升**。原因是本次实验的对手是**固定的 GATHER 人类代理**——当搜索内部的人类模型恰好等于对手的真实策略时，最坏情况建模与单动作预测的差别只体现在"多余的分支"上，并不改变最优动作的选择（33% 的分歧都发生在多个候选对 AI 等价的局面上）。要检验人类模型的影响，需要让**对手策略与搜索内部模型不一致**（例如对手用 RATIO/CAUTIOUS，而 AI 分别按 GATHER 与 worst_case 建模）。

> 局限：本轮 A/B 只有 24 局配对，置信区间很宽；对战均值（41 次/局）明显高于 §7.1 的正式样本（1.68 次/局），提示这批小样本落在 §7.7 所述的往复循环区间内，配对结论仅作方向性参考。

### 7.11 需求第八节五项亮点的证据映射

| 亮点 | 观察到的证据 | 反证 / 边界 |
| --- | --- | --- |
| 多模式分层难度 | EASY 路由贪心（0.28 ms/决策）、NORMAL/HARD 路由 OPT（31 ms/决策）；仅 HARD 隐藏未触发陷阱 | 难度**不单调**：v2 下 AI 胜率（严格）EASY 0.222 < NORMAL 0.483 < HARD 0.589，因为 CAUTIOUS 在 HARD 会踩陷阱而**削弱了人工**；不能声称"HARD 对人类更难"——那是相对 AI 的分差 |

## 8. 局限性

1. **搜索规模由"深度"单独决定，而非地图大小或资源数量**。实测（见 §7.11）：depth 每加一层，节点数 ×6.6～11.5；而地图从 8×8 到 14×14、宝藏 4→30 个，节点数只在 1.6× 内波动。默认 depth = 3 是工程折中，depth = 4 实测 14,484 节点 / 2.5 s（12×12, N=3）。设计文档给出的 `O(K(6K)^(d−1))` 是**保守上界**，实际候选被约束到个位数，真实节点比该上界小 3 个数量级。"最优"仅指**给定深度与候选集内**的最优。
2. **人工代理不是真人**：座位 A 是确定性启发式代理（`GATHER` / `CAUTIOUS`），不能代表真实人类的策略多样性。§7.2 与 §7.5 的结论差异恰好说明：**代理是否使用可见信息，会决定可见性实验的结论**。
3. **座位优势未对调**：全程固定 A = 人工、B = 机器，未做 A/B 对调实验，因此不能排除先手/座位带来的系统性偏差。
4. **分治是近似**：跨块路径经全图 BFS 与全图重放验证合法性，但局部关注目标集合会丢弃跨块长远互动；§7.4 显示逐决策动作一致率仅 34.5%。
5. **困难模式是单向隐藏**：仅对人工隐藏陷阱，机器 AI 始终读取底层真值。双向未知需要 POMDP / 信念状态，属选做未做。
6. **α-β 在本问题近似无效**：机会节点的精确期望使窗口无法收紧；带区间界的剪枝已实现但实测不减少节点。报告不宣称剪枝带来加速。
7. **代理病理行为**：`CAUTIOUS` 在"陷阱挡住必经之路"时会产生往复循环（§7.6），导致个别对局对战次数与分数爆炸。这是代理设计问题，但会污染聚合均值，故报告以中位数与病态局占比为主口径。
8. **地图生成的成功率约束**：`MapModule.generate` 采用"打乱分配 + 最多 1000 次重试"，自由格占比低于约 62% 时会失败（这是需求 D3 的语义而非缺陷）。实验固定使用低墙密度配置。
9. **GUI 视觉验证有限**：动画与弹窗在 offscreen 模式下只能验证逻辑与状态，真实渲染效果需有显示器的环境人工确认。

## 9. 总结与后续工作

### 9.1 结论（限定在本报告的地图规模、代理模型、深度与硬件范围内）

1. **规格落地完整**：三模式、六大模块、两套 AI、控制台七菜单、批量仿真全部可运行；需求第七节 5 个关键用例自动化通过；全量回归 374 passed。
2. **OPT 显著优于贪心**：净分差 +16.51、AI 胜率（严格）+0.211（宽松 +0.189）、自身踩陷阱 −0.64、主动对战 +1.32，全部统计显著。这验证了"简单模式用贪心做教学基线、普通/困难用博弈搜索"的分层设计。
3. **陷阱可见性只有在被使用时才可见**：这是本实验最有价值的方法论结论。同一个"NORMAL vs HARD"对照，用陷阱盲代理得到 0 差异，用会避让的代理得到 50/90 单元分歧显著；该结论在 10×10 单体 OPT 基线上独立复现（人工踩陷阱 0.00 → 1.00，分差配对差 +3.69，CI [+0.26, +8.10]）。**做可见性消融实验时，必须确认代理具备使用该信息的能力，否则会得到虚假的零结果。**
4. **可见性代价随陷阱密度单调上升**：人工踩陷阱差值 0.30 → 1.03 → 2.13（陷阱数 2 → 6 → 12），稳健分差差值 +2.07 → +4.47 → +6.28。
5. **分治值得在大图上使用**：同网格同 seed 对照下 4.8–5.7× 加速，平均效用无可检出损失，胜率不降反升；代价是决策路径与单体差异很大，适合"规模优先"场景而非"可复现单体策略"场景。
